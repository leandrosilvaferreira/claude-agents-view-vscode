Claude Code appends one `{"type":"cost-state", sessionId, totalCostUSD, …}` line (no `timestamp`, no `message`) when its process shuts down — and, through the same saver, at `/clear` and on an in-process conversation switch. Local census (2026-09-28, 610 transcripts, 652 markers, 2.1.227–2.1.284): 637 are followed by nothing but bookkeeping to EOF (606 as the literal last line); 15 are followed by real turns of a later process resuming the same session id (fresh processes, usually opening with queue-operation/attachment lines); every interactive session on 2.1.278+ that ended cleanly has one (88/88). A dead process's subagent transcripts never grew more than 3.3 s past it. Absent on: hard kills (SIGKILL, crash, power loss), VS Code/SDK sessions before 2.1.278, headless `sdk-cli` runs that never called the API.
**Why:** nothing else in the parent transcript says background subagents died (`system:agents_killed` is only written on interrupt). The 2.1.283 -> 2.1.284 auto-update exited three sessions in one second while agents ran: the old sessions read 'working' for `IDLE_CEILING` (the marker write itself refreshes the mtime, restarting the clock), then 'stopped' with a full "Working Agents" group until the 1 h cutoff — a ghost duplicate row beside the successor session. The successor is a NEW session id with a NEW ai-title, so `getDedupeKey` cannot merge them (title is part of the key), and that is by design. Cost ~2 h to pin down (2026-09-28).
**How to apply:** treat the marker as a latch (`Session.shutdownRecorded` — set by `cost-state`, cleared by the next message-bearing turn) that outranks every mtime heuristic (there is no lsof signal any more — removed in 0.6.0), and stop every still-working subagent (foreground too, no `stoppedAt`, so no re-wake) plus grandchildren. Known limit: a `/background` fork that KEEPS its parent snapshots mid-session (in the CLI binary, never in the corpus) — the parent's live subagents would be stopped early. Not used: `~/.claude/sessions/<pid>.json`, the per-process registry (pid, sessionId, cwd, procStart, kind, status; written at start, unlinked on graceful exit only; `updatedAt` is not a heartbeat; needs a per-OS process start-time check against pid recycling). It is the authoritative "alive now" signal if hard-kill ghosts ever appear — none in 14 days.
